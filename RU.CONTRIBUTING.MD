# Как помочь проекту

Спасибо, что решили поучаствовать. Здесь всё, что стоит знать до того, как открывать пул-реквест.

**In English: [CONTRIBUTING.md](CONTRIBUTING.md)**

## Как начать

```bash
git clone https://github.com/Vadim-Khristenko/awg-containers-and-tools
cd awg-containers-and-tools
cargo test --workspace
```

Нужен Rust 1.90 или новее — воркспейс на edition 2024. Для всего, что касается контейнеров, понадобится ещё Docker, а тестовым скриптам нужно создавать tun-устройства, то есть root.

## Перед пул-реквестом

```bash
cargo test --workspace                     # все тесты зелёные
cargo clippy --workspace --all-targets     # ноль предупреждений
cargo fmt --check
```

Если трогали что-то в `containers/`:

```bash
cd containers
./build.sh
sudo ./selftest.sh        # живой туннель на каждое поколение
sudo ./paralleltest.sh    # все четыре одновременно
sudo ./dnstest.sh         # защита от утечек всё ещё держится
```

Это медленно, но именно здесь проходит граница между «оно собирается» и «оно везёт трафик». Контейнерная часть проекта уже не раз выпускала баги, которые видно только на живом туннеле.

## С чем пул-реквест вернут

**Инварианты протокола — это не вопрос вкуса.** Генератор отказывается выдавать некоторые сочетания, потому что настоящие демоны их не принимают, и причины записаны рядом с проверками. Если правило валидации мешает — сначала выясните, откуда оно взялось. Вот что эти правила кодируют:

- нижняя граница S при включённой защите заголовков
- обязательное соотношение таймеров rekey и reject
- какие теги мусорных пакетов реально принимает каждая версия протокола: демоны 1.5 отвергают `<rc>` и `<rd>` с `errno=-22`, а `<c>` не реализован в 2.0 и 3.0
- потолки размеров, удерживающие мусорные пакеты внутри MTU

Каждое из них нашлось не в спецификации, а в момент, когда демон отказался принимать конфиг.

**Не добавляйте общий набор параметров по умолчанию.** Параметры рандомизируются на каждую установку намеренно. Встроенные дефолты дали бы всем серверам, поднятым этим инструментом, одинаковый DPI-отпечаток, и одна сигнатура положила бы их все разом. Это самое важное проектное ограничение во всём репозитории.

**Не ослабляйте генерацию ключей.** Ключевой материал берётся из CSPRNG операционной системы. Любой seeded или thread-local генератор рядом с ключами — это дыра в безопасности, а не оптимизация.

**Не пишите секреты в логи.** Журнал событий задуман так, чтобы его можно было отдать тому, кто помогает вам разобраться. Ключам, pre-shared-ключам и `HeaderProtectionKey` там не место.

## Тесты

Новое поведение нужно покрыть тестом. Логика протокола в `awg-core` намеренно написана чистыми функциями от входных данных — генерация параметров, валидация, рендеринг и определение системы принимают данные и возвращают данные, — так что почти всё тестируется без сети, контейнера и сервера. Если ваше изменение трудно протестировать, это обычно значит, что его стоит разбить.

Называйте тест по поведению, которое он защищает, а не по функции, которую он вызывает. `nixos_is_never_given_an_imperative_command` сразу говорит следующему человеку, что сломалось; `test_plan_3` — нет.

## Сообщения коммитов

Conventional commits:

```
type(scope): краткая суть в повелительном наклонении

Зачем понадобилось изменение, если это не очевидно из заголовка.
```

Используемые типы: `feat`, `fix`, `docs`, `refactor`, `test`, `build`, `chore`. Scope повторяет структуру репозитория — `awg-core`, `awg-cli`, `containers`, `ci`.

Тело коммита пишите для человека, который прочитает его через год и ничего не будет помнить об обсуждении.

## Как сообщать о багах

Полезный отчёт содержит:

- версию протокола и клиента
- сгенерированные параметры **с вырезанными ключами**
- что сказал демон — вывод `awg-uapi get` и лог контейнера
- на чём именно ломается: на импорте, на хендшейке или уже после начала трафика

Никогда не вставляйте в issue приватные ключи, pre-shared-ключи и значения `HeaderProtectionKey`. Если уже вставили — перегенерируйте их.

## Границы проекта

Здесь намеренно не будет:

- публичного сервера или какого-либо хостинга
- конфигурации по умолчанию, рассчитанной на всех сразу
- заявлений о связи с AmneziaVPN

Issue с такими просьбами будут закрыты со ссылкой сюда.
