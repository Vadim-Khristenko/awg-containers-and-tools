# AmneziaWG: справка для агента

Помогай работать с существующими инструментами проекта, не придумывая новые
скрипты, команды или слой управления. Это неофициальный community-проект,
не официальный установщик AmneziaVPN. Отвечай на языке пользователя;
справка написана по-русски, команды и идентификаторы оставлены исходными.

## Навигация

Пути `references/...` относительны каталогу этого `SKILL.md`; пути
`containers/...`, `crates/...` и `README.md` — корню репозитория.

| Задача | Что прочитать |
|---|---|
| Сборка CLI, требования, новый сервер, SSH или Compose | [references/installation.md](references/installation.md) |
| Выбор версии/клиента, генерация, `.conf`, переменные, DNS, маршруты | [references/configuration.md](references/configuration.md) |
| Новое устройство, сохранение конфига, full/split tunnel, отзыв доступа | [references/clients.md](references/clients.md) |
| Status, doctor, logs, health, обновление, резервирование, вклад в код | [references/operations.md](references/operations.md) |
| Сценарии проверки ответов агента | [evals/evals.json](evals/evals.json) |

Читай только необходимые разделы, но при добавлении клиента сначала проверь
ограничения выдачи в `clients.md`: они влияют на безопасность и совместимость.

У ручного CLI-парсера различай флаги со значением и presence-only переключатели.
Для выключенных `RandomTrailers`/`DisableCookies` **опусти** `--random-trailers`
и `--disable-cookies`: запись `--disable-cookies off` всё равно включает режим.
Значение `off` принимает отдельный флаг `--narrow-h`, не все булевы опции.

## Порядок работы

1. **Определи задачу и контекст.** Нужна инструкция или выполнение? Новый
   сервер или существующий? Локальный Docker, сервер по SSH или приложение на
   телефоне? Не запускай установку ради ответа на вопрос.
2. **Сначала наблюдение.** Найди действующий Compose, имя/образ контейнера,
   поколение протокола, интерфейс, опубликованный UDP-порт, state-volume и
   фактический endpoint. Используй `awg-tool status --local` либо явно выбранный
   remote профиль. Не печатай конфигурации с ключами в чат.
3. **Выбери один рабочий путь.** Для управляемой удалённой установки —
   `awg-tool install`. Для ручной контейнерной установки — Compose. Для нового
   устройства на работающем контейнере — `awg-peer`, не новый `install`/`gen`.
4. **Сверь текущее поведение.** `awg-tool --help` и исходники checkout важнее
   исторических примеров README. У CLI ручной парсер: наличие неизвестного
   флага в команде не доказывает, что он сработает. Не изобретай `awg-tool peer`,
   `export`, `backup`, `server add` или `--yes`.
5. **Уточни только недоступные из окружения решения.** Для реального развёртывания
   нужны целевой host/SSH, доступный клиентам endpoint, порт, целевое приложение
   и full/split tunnel. Не проси пользователя присылать приватные ключи.
6. **Изменяй после согласования риска.** Установка пакетов/Docker, перезапись
   серверного `.conf`, открытие firewall, перезапуск, отзыв peer и удаление
   данных затрагивают доступ. Назови точный узел, изменение и возможный обрыв.
   Не принимай вопрос «как установить» за разрешение выполнить команды на сервере.
7. **Проверь результат на нужном конце.** `errno=0` значит, что демон принял
   конфиг; `healthy` — что интерфейс/UAPI живы. Рабочий VPN подтверждают
   handshake после трафика, изменение rx/tx, DNS и доступ к нужному ресурсу
   с реального клиента. Не объявляй успешной удалённую установку по одной сборке CLI.

## Инварианты

- Согласуй поколение образа, допустимые ключи и приложение клиента. Нельзя
  включать поля 3.1 в 3.0 и считать ограничение Windows H несущественным.
- Для одной серверной конфигурации используй один согласованный блок
  обфускации; не генерируй новый для каждого добавленного устройства.
- Выдаваемый `.conf` и `vpn://` — секреты. PrivateKey, PSK,
  HeaderProtectionKey, SSH-пароли и сырой UAPI не попадают в Git/issue/лог ответа.
- Сохраняй `/var/lib/awg` и исходный серверный конфиг: live peer без
  постоянного источника после пересоздания исчезнет. Для `.conf`-peer одного
  `awg-peer rm` недостаточно: entrypoint восстановит его при следующем запуске.
- Не публикуй внутренний DNS/HTTP наружу и не обещай полный kill switch:
  изоляция DNS bridge не управляет fallback/DoH/IPv6 на устройстве.
- Не исправляй проблему через `--privileged`, отключение firewall/проверки
  SSH host key, удаление volumes, `curl | sh` или запуск чужого установщика.
- Не меняй код ради обхода ограничения, если запрос только на эксплуатацию.
  Объясни ограничение и выбери поддержанный путь; новые скрипты не нужны.

## Формат ответа

Для инструкции укажи: выбранный путь и предпосылки → команды с местом запуска
→ ожидаемый проверяемый результат → что делать при характерной ошибке.
Отделяй примеры от готовых к выполнению команд, не оставляй фиктивные ключи в
файле, который предлагается немедленно запускать.

После выполнения назови конкретный узел/контейнер, что изменено, где сохранён
секретный артефакт (без содержимого), какие проверки реально выполнены и что
не удалось проверить. Для ошибки: наблюдение → подтверждённая причина либо
гипотезы → минимальная следующая проверка. Не подменяй отсутствие данных
уверенным диагнозом.
