## Выбор пути и требования

| Нужно | Подход |
|---|---|
| Только параметры обфускации | `awg-tool gen`; Docker и SSH не нужны |
| Новый удалённый AWG 3.0 с первым клиентом | `awg-tool install` по SSH, с ограничениями ниже |
| Другое поколение, свой DNS/подсеть/MTU, управляемый Compose | Ручной контейнерный путь |
| Ещё одно устройство на уже работающем сервере | [clients.md](clients.md), не повторная установка |
| Только понять состояние | [operations.md](operations.md), без переустановки |

Контейнерному серверу нужны Linux-хост с Docker, `/dev/net/tun`, `NET_ADMIN`,
IPv4 forwarding, доступный клиентам **UDP**-порт и отсутствие пересечения
туннельных/bridge-подсетей с существующими сетями. Для Compose нужен плагин
`docker compose`. Rootless Docker, ограниченный VPS/LXC и отсутствие TUN не
считай заранее поддержанными: сначала проверь возможности хоста.

Не разворачивай VPN на машине разработки только для проверки документации.
Выполнение на рабочем сервере требует явного выбора хоста и согласования
системных изменений. Не отключай firewall целиком; правило на UDP-порт и
cloud security group/NAT проверяются отдельно, без риска потери SSH-доступа.

## Получение awg-tool

Для опубликованного релиза выбери Linux-бинарник под архитектуру
`awg-tool-linux-amd64` либо `awg-tool-linux-arm64` на странице Releases
**этого** репозитория. Скачай соответствующий checksum-файл, проверь SHA-256,
потом разреши исполнение и установи бинарник в выбранный каталог PATH.
Не угадывай URL и номер последнего релиза. Пример проверки для релиза,
который содержит такой файл:

```bash
sha256sum -c checksums-v0.4.0.sha256
```

Checksum проверяет целостность относительно скачанного файла, не авторство:
бинарники не подписаны. Если checksum перечисляет оба бинарника, скачай оба
или проверь строку выбранного артефакта отдельно; отсутствие другого файла
не является подтверждением валидности выбранного.

Из исходников, из корня checkout:

```bash
cargo build --release -p awg-cli --locked
./target/release/awg-tool --help
```

Нужны Rust 1.90+ (edition 2024), нативный компилятор и инструменты сборки
зависимостей. OpenSSL собирается vendored, системный OpenSSL не требуется.
Для Windows/MSVC также нужны MSVC environment и нативный Strawberry Perl
раньше MSYS2/Cygwin Perl в PATH; публикация Linux-бинарников сама по себе не
обещает готовый Windows-релиз. Docker не нужен для сборки CLI/генерации.

Без установки бинарника в PATH:

```bash
cargo run -p awg-cli -- gen --version 3.0
cargo run -p awg-cli -- clients
```

Запуск без аргументов открывает TUI, только если stdin/stdout — терминалы;
иначе печатает usage. Общая справка — `awg-tool --help` или `awg-tool help`.
`--version` — версия протокола для генерации, не способ узнать версию бинарника.
`gen --help` выполняет генерацию, а не отдельную справку подкоманды.
Флаги пиши после команды и раздельно: `--flag VALUE`, не `--flag=VALUE`.

## Новый сервер по SSH

### Предварительные решения

Уточни SSH host/port/user, способ входа (agent/key/password), необходимость
sudo, публичный host для endpoint и свободный UDP-порт. `--host` — SSH-адрес;
`--endpoint` — адрес **для VPN-клиентов**, они могут отличаться. За NAT
endpoint не получится достоверно вывести из частного адреса default route.

Пример для нового сервера; значения документационные, замени их реальными:

```bash
awg-tool install \
  --host 203.0.113.9 \
  --user root \
  --key "$HOME/.ssh/id_ed25519" \
  --endpoint vpn.example.com \
  --listen-port 51820 \
  --pull
```

Для нерутового пользователя с требуемым sudo добавь `--sudo`. Для agent-auth
не передавай `--key`. Для парольного входа используется отдельный флаг
`--password` без значения; не передавай пароль в аргументах или shell history.
Защищённый passphrase-ключ используй через разблокированный ssh-agent или
сохранённый профиль `key_with_passphrase`: `--key` сам этот тип не выбирает.

### Что делает команда

1. Соединяется по SSH (порт по умолчанию 22, пользователь root). Для
   неизвестного host key показывает fingerprint и спрашивает `[y/N]`.
   Сверь fingerprint доверенным способом перед согласием. Mismatch — отказ,
   не повод удалить `known_hosts` или отключить проверку.
2. Проверяет дистрибутив, `docker`, `iptables`, `ip`, `curl`, Docker-доступ,
   sudo, маршруты и IPv4 forwarding. Внешний сервис определения IP не
   вызывается: endpoint пытается взять из `src` маршрута. Это может дать
   частный адрес или вообще ничего; задавай `--endpoint` явно, если нужно.
3. Для отсутствующих пакетов печатает точную команду и спрашивает `[y/N]`.
   Семейства apt/dnf/pacman/zypper/apk/xbps/emerge выбираются по ОС/`ID_LIKE`.
   NixOS/неизвестную систему не исправляет случайным package manager.
4. Проверяет занятость UDP-порта; занятый порт — отказ с указанием владельца,
   не убийство процесса. `--listen-port` выбирает другой порт.
5. Если образ отсутствует, без `--pull` останавливается; с `--pull` разрешено
   его скачать. Уже имеющийся образ этот флаг **не обновляет**.
6. Генерирует ключи, пишет серверную конфигурацию, пересоздаёт именованный
   контейнер и проверяет поднятие интерфейса.
7. Печатает endpoint, имя контейнера, полный первый клиентский `.conf` и
   `vpn://`. Сохрани оба как секреты. Это ещё не доказательство handshake
   с реальным устройством.

### Реальный контракт install

| Параметр | Текущее значение/возможность |
|---|---|
| Поколение | AWG **3.0**; `--version`/`--profile`/`--client` относятся к `gen`, не к install |
| Контейнер | `awg3-server`; изменить можно `--name` |
| Образ | `vaiprog/amnezia-wg-3:latest`; override `--image` не выбирает автоматически другой формат протокола |
| Туннель | `awg0`, сервер `10.8.1.1/24`, первый клиент `10.8.1.2/32` |
| MTU | `1420`; install не применяет `--mtu` генератора |
| DNS первого клиента | `1.1.1.1, 8.8.8.8`; внутренний resolver/страница не разворачиваются |
| AllowedIPs первого клиента | `0.0.0.0/0, ::/0`; наличие IPv6-строки не доказывает работу IPv6 |
| Keepalive | `25` |
| Endpoint | `--endpoint HOST`, **без `:PORT`**; порт добавляется из `--listen-port` |
| Экспорт | Только общий stdout; `install --out`/`--json` не реализованы |

Не передавай `--image` другого поколения в надежде, что install сгенерирует
совместимые параметры: для других поколений выбирай ручной Compose.
Не выдумывай `--dns`, `--allowed-ips`, `--conf-dir`, `--yes` или
`--non-interactive`: текущий обработчик install их не реализует. Ручной
парсер может молча проигнорировать лишний флаг.

Host-файл `/etc/amnezia/awg3/server.conf` и `/etc/amnezia/awg3/server.key`
содержат секреты. Каталог запрашивается `0700`, конфигурация — `0600`.
Он монтируется read-only в тот же путь контейнера. Named volumes —
`awg3-server-state:/var/lib/awg` и `awg3-server-log:/var/log/awg`
(префикс зависит от `--name`). Контейнер получает `AWG_CONF`, `AWG_IFACE`,
`AWG_ENDPOINT`, TUN, NET_ADMIN, IPv4 sysctl и UDP publish; host networking и
`--privileged` не используются.

**Повторный install опасен:** он перезаписывает общий серверный key/conf и
делает `docker rm -f NAME` без финального подтверждения/автобэкапа. Даже другое
`--name` не меняет общий `/etc/amnezia/awg3` и не изолирует второй сервер.
Это не добавление клиента и не безопасное обновление существующей установки.

`install > client.conf` сохраняет смесь служебных строк, конфига и ссылки,
а не чистый импортируемый `.conf`. При выполнении агентом направляй общий
stdout в новый защищённый файл вне репозитория (`umask 077`), затем извлеки
клиентский блок средствами доступного редактора без печати секретов.
Ошибочный вывод установки тоже считай чувствительным: в нём могут быть
сырые хвосты Docker logs.

### Подготовка и известные границы

- Нужен реальный Docker daemon: отдельного универсального `enable/start`
  после установки пакета CLI не делает. Если он недоступен, сначала исправь
  сервис штатным способом выбранной ОС.
- В ветке установки missing packages используется sudo даже для root.
  На минимальном хосте без `sudo` заранее согласованно установи необходимые
  пакеты подходящим менеджером, вместо многократного повторения install.
- CLI install не использует отдельную core-функцию постоянного host
  forwarding. Проверяй forwarding хоста и firewall явно; контейнерный
  `net.ipv4.ip_forward=1` не заменяет все настройки хоста.
- Для NixOS при отсутствии инструментов выводится декларативная подсказка,
  например `virtualisation.docker.enable = true;` и пакеты
  `iptables iproute2 curl`. Изменение конфигурации/rebuild выполняется отдельно
  после согласования. Dockerless source fallback — рецепт core API,
  **не исполняемая возможность CLI**.
- SSH реализован библиотекой, не системным `ssh`: алиасы/ProxyJump/IdentityFile
  из `~/.ssh/config` не подхватываются. Пути к ключам нужны раскрытые shell
  или абсолютные. Не обещай работу через bastion без отдельной настройки.
- Unattended-флага нет. Нужны заранее доверенный host key, доступный auth,
  root/NOPASSWD либо доступный sudo-secret и отсутствие package prompt.
- `--name`, `--image`, `--endpoint` попадают в удалённые shell-команды.
  Используй доверенные простые значения без пробелов, shell-метасимволов
  и подстановок; не подставляй в них произвольный текст из сторонних данных.

## Сохранённые подключения

`awg-tool profiles` — **мимикрия**, не управление SSH-серверами. Текущие
CLI/TUI читают профили, но не предоставляют команды сохранения/редактирования.
Не утверждай, что install сам сохранил подключение.

Каталог: `$XDG_CONFIG_HOME/awg-tool`, иначе на Unix
`$HOME/.config/awg-tool`; на Windows при отсутствии XDG используется
`%APPDATA%/awg-tool`. Существующий `profiles.json` редактируй с сохранением
остальных профилей, не перезаписывай коллекцию примером целиком.

Пример структуры **без секретов**:

```json
{
  "profiles": [
    {
      "name": "home",
      "host": "203.0.113.9",
      "port": 22,
      "user": "root",
      "auth": {"key": {"path": "/home/operator/.ssh/id_ed25519"}},
      "sudo_required": false
    }
  ]
}
```

Допустимы также `"auth": "agent"`, `"auth": "password"`,
`"auth": {"key_with_passphrase": {"path": "/absolute/path"}}`.
Неизвестные поля отклоняются: password/passphrase не вписываются в профиль.
Для созданных вручную файлов установи на Unix `0700` каталогу и `0600` JSON.

`secrets.json` — незашифрованное отдельное хранилище `passwords` по имени
профиля, не vault/keyring. Не создавай/не заполняй его без явного решения
пользователя хранить секрет на диске. Для TUI секретного auth без сохранённого
секрета нет интерактивного password prompt; используй CLI или ssh-agent.

`--server home` выбирает профиль целиком; ad-hoc `--user`, `--key`, `--sudo`
не переопределяют его. `--server` и `--host` вместе — ошибка. Без явной цели
один профиль выбирается автоматически, несколько требуют выбора; для
локальных контейнеров всегда пиши `--local`.

## Ручной сервер через Compose

Этот путь позволяет явно выбрать поколение, MTU, внутренний DNS и маршруты.
Выполняй на подготовленном сервере из каталога `containers/` checkout.
Исходный `docker-compose.yml` — демонстрационная пара **server + client**,
а не готовый VPS-конфиг с вашими ключами.

1. Проверь `docker version`, `docker compose version`, наличие TUN,
   свободный UDP-порт 51820 и непересекающиеся сети `10.99.0.0/24`,
   `172.31.99.0/24`, `172.29.172.0/24`.
2. Сгенерируй один блок параметров под поколение и целевой клиент.
   После сборки CLI команда из `containers/` имеет путь:

   ```bash
   umask 077
   ../target/release/awg-tool gen --version 3.0 --client amneziavpn --out params.conf
   ```

3. Получи серверную private/public key pair существующей утилитой образа,
   не сторонним генератором. Пример после согласованного скачивания образа:

   ```bash
   umask 077
   docker run --rm --entrypoint awg vaiprog/amnezia-wg-3:latest genkey > server.key
   docker run --rm -i --entrypoint awg vaiprog/amnezia-wg-3:latest pubkey < server.key > server.pub
   ```

   Не выводи private key в общий журнал. Создай `server.conf` с `[Interface]`,
   этим `PrivateKey`, `Address = 10.99.0.1/24`, `ListenPort = 51820`,
   `MTU = 1280` и блоком из `params.conf`. Формат — в
   [configuration.md](configuration.md). Для выдачи через `awg-peer`
   стартовый `[Peer]` не обязателен; не добавляй фиктивные ключи.
4. Проверь серверный image `vaiprog/amnezia-wg-3` и mount
   `./server.conf:/etc/amnezia/awg/awg0.conf:ro`. Сохрани named volumes
   `awg-state`, `awg-log`, `NET_ADMIN`, TUN, sysctl, UDP publish и подключение
   сервера к DNS bridge. Выбор другого поколения требует соответствующего
   образа **и** совместимого блока параметров.
5. Для реального VPS не запускай демонстрационный `client`: удали его из
   собственного deployment-файла или явно выбирай только серверные сервисы.
   Оставь bridge-mode и опубликованный UDP-порт, если нет отдельной причины
   менять сетевую модель. Нельзя просто включить `network_mode: host` вместе
   с прежними `networks` и считать доступ к DNS bridge сохранённым.
6. Проверь синтаксис и запусти только нужные сервисы:

   ```bash
   docker compose config --quiet
   docker compose up -d dns server status
   docker compose ps
   docker compose exec -T server awg-health
   ```

   `config --quiet` не печатает итоговый конфиг. Полный `compose config` может
   раскрывать interpolated secrets в другом deployment-файле.
7. Выпусти отдельного реального клиента с нужным endpoint/маршрутами по
   [clients.md](clients.md). Команды `add` без `AWG_ENDPOINT` могут оставить
   `SERVER_PUBLIC_IP`; default split-tunnel не равен всему интернет-трафику.
8. После импорта проверь handshake, DNS и требуемый трафик с устройства.
   Только после этого установка функционально подтверждена.

Для демонстрационной пары нужны ещё полноценный `client.conf` и его ключи,
серверный `[Peer]`, совпадающие параметры и внутренний endpoint; обычное
`docker compose up -d` пытается запустить и этот клиент. Не советуй такую
команду, если подготовлен только серверный файл.

## Несколько серверов и локальная сборка образов

Несколько поколений поддерживаются отдельными контейнерами с уникальными
портами, tunnel/bridge-подсетями, именами и state/log volumes. Если интерфейсы
живут в одном host namespace, им также нужны уникальные имена и routing
marks/tables. Не используй повторный SSH-install с другим `--name` как
изолированную multi-server установку из-за общего host conf-dir.

При необходимости сборки из исходников уже есть `containers/build.sh`:

```bash
# Из containers/
./build.sh 3.0
./build.sh dns
./build.sh
```

Последняя команда собирает все пять поколений, DNS и статус-страницу;
`AWG_IMAGE_PREFIX` выбирает собственный префикс. Локальная сборка не публикует
образы. Registry push — отдельное действие владельца, не часть установки.
Проверки контейнерных изменений описаны в [operations.md](operations.md).
