## Источники и выбор поколения

Пути в этом разделе отсчитываются от корня репозитория. Сверяй актуальные возможности с `crates/awg-core/src/versions.rs`, обработку `.conf` — с `containers/entrypoint.sh`, топологию — с `containers/docker-compose.yml`. Документация не заменяет код текущего checkout.

| Версия | Образ | Набор параметров |
|---|---|---|
| 1.0 | `vaiprog/amnezia-wg-1` | `Jc/Jmin/Jmax`, `S1/S2`, фиксированные `H1–H4`; без `I1–I5` |
| 1.5 | `vaiprog/amnezia-wg-15` | Дополнительно клиентские `I1–I5`; свой словарь тегов цепочек |
| 2.0 | `vaiprog/amnezia-wg-2` | `S3/S4`, диапазоны H, новый словарь цепочек |
| 3.0 | `vaiprog/amnezia-wg-3` | `HeaderProtectionKey`, `ContentPaddingAddition`, диапазоны таймеров |
| 3.1 | `vaiprog/amnezia-wg-31` | Дополнительно `RandomTrailers`, `DisableCookies` |

Это разные поколения протокола, а не взаимозаменяемые теги одного конфига. Выбирай поколение по реальной поддержке приложения на каждом устройстве, а не только по названию клиента. Новый `--client` ограничивает генерируемые значения, но не обновляет приложение.

Словарь цепочек 1.5 и 2.0+ не является вложенным:

- 1.5 понимает `b c t r wt`; `<c>` и `<t>` уникальны в пределах цепочки. Генератор не выпускает `wt`.
- 2.0+ понимает `b t r rc rd d ds dz`, но не `c`/`wt`. Генератор использует поддерживаемое им подмножество, а не все понимаемые демоном теги.
- Не переносить `<rc>`/`<rd>` в 1.5 и не принуждать `<c>` в 2.0/3.x. Ошибка `invalid i1: invalid tag: rc` требует верной версии генерации, а не удаления всей обфускации.
- В 1.5 цепочки отправляет клиент. При ручной подготовке пары сохраняй клиентский блок; не делай вывод о сломанном соединении только из отсутствия `I1–I5` на сервере.

## Генерация параметров

Команды выполняются из корня репозитория с установленным `awg-tool`; без установки используй `cargo run -p awg-cli --` вместо `awg-tool`.

```bash
awg-tool profiles
awg-tool clients
awg-tool gen --version 3.0 --profile quic --client amneziavpn
awg-tool gen --version 2.0 --client amneziawg-windows --browser chrome
awg-tool gen --version 3.0 --profile tls --host cdn.example.com
awg-tool gen --version 3.0 --uapi
```

`gen` генерирует блок обфускации, **не готовый сервер**, не ключевую пару клиента и не регистрацию peer. Новый запуск даёт новый набор. Для одной пары сгенерируй блок один раз и сохрани совпадающие параметры на обоих концах. Для существующего сервера не запускай новую генерацию только ради добавления устройства: это рассинхронизирует его с остальными клиентами.

`gen --host` — имя для пакетов мимикрии (например SNI), а не SSH-адрес или `Endpoint`. Смысл флага зависит от подкоманды.

Профили: `quic`, `quic0rtt`, `tls`, `noise`, `dtls`, `http3`, `sip`, `tls-to-quic`, `quic-burst`, `dns`, `random`. Актуальный перечень смотри через `profiles`.

Клиенты в матрице: `amneziawg-android`, `amneziawg-ios`, `amneziawg-windows`, `amneziavpn`, `wg-tunnel`, `wiresock`, `keenetic-native`, `awg-go-legacy`, `openwrt`, `asus-merlin`. Перепроверь идентификатор через `clients` перед командой: имя в интерфейсе и CLI-id могут отличаться.

- У AmneziaWG Windows H ограничены `2_147_483_647`; генерация под другой клиент может создать неимпортируемый файл.
- Для WireSock не выдавай неподдерживаемые теги цепочек; для Keenetic предпочитай простую мимикрию и умеренную нагрузку.
- Большие S4 и длинный junk-train увеличивают расход трафика/CPU/батареи. Не включай `--extreme` для «починки» соединения без измерений.
- `--junk` принимает 0..32, default 5, но итог ограничивается версией/клиентом: у 1.0 даже `--junk 0` даёт минимум Jc=4; `--extreme` тоже может снова включить junk. Проверяй выданный Jc, а не обещание по названию флага.
- `--narrow-h` — обход CPU-проблемы 3.1 с узкими окнами H, а не универсальный ускоритель. Для 3.1 включён по умолчанию; `--narrow-h off` его отключает, для других версий не применяется.
- `--random-trailers` и `--disable-cookies` относятся к 3.1; оба по умолчанию выключены. Это **presence-only** флаги без значения: для выключения не передавай флаг вообще. `--random-trailers off`, `--disable-cookies off`, `false` или `0` после флага не выключают режим — наличие флага уже включает его. Не переноси синтаксис `--narrow-h off` на эти переключатели. `DisableCookies` убирает защиту под нагрузкой и может нарушить NAT keepalive; не включай автоматически.
- Даже если матрица клиента допускает `<c>`, допустимость тега определяется также поколением протокола.

Основные флаги `gen` и значения по умолчанию:

| Флаг | Default | Смысл |
|---|---|---|
| `--version` | `3.0` | Поколение протокола |
| `--profile` | `quic` | Мимикрия I1 |
| `--client` | `amneziavpn` | Ограничения значений и тегов |
| `--intensity` | `medium` | `low`/`medium`/`high`; неизвестное значение трактуется как medium |
| `--mtu` | `1500` | MTU пути для генерации, 576..9000; не устанавливает tunnel MTU в готовом сервере |
| `--router` | Выкл. | Умеренные junk/padding для слабого устройства |
| `--browser` | Не задан | Размеры chrome/edge/firefox/safari/yandex-desktop/yandex-mobile |
| `--mimic-all` | Выкл. | Выбранный профиль для всех пяти I-пакетов |
| `--uapi` | Выкл. | Строки параметров UAPI, не полный запрос `set=1` с ключами и peers |
| `--json` | Выкл. | JSON с version/profile/params/lines |
| `--out PATH` | stdout | Запись представления в файл, с перезаписью существующего |
| `--lang` | По окружению | `en`/`ru`; приоритет выше `AWG_LANG`, `LC_ALL`, `LANG` |

`--tag-c` в текущем генераторе не принуждает тег: фактическое разрешение
определяется версией и клиентом, для 1.5 `<c>` может появляться автоматически.
Старые версии молча игнорируют флаги 3.1. Не проверяй поддержку опции только
по успешному exit code.

При `--json --uapi` точные данные находятся в `lines`, а объект `params`
остаётся пустым из-за способа разбиения строк. `--out` не устанавливает 0600:
перед созданием нового файла используй `umask 077`, существующему проверь
права отдельно. Блок 3.x содержит секретный HeaderProtectionKey, поэтому
`params.conf` тоже не следует коммитить.

## Структура конфигураций

Шаблоны ниже показывают структуру, **не готовы к запуску**: замени все значения в угловых скобках реальными ключами и вставь блок генератора. Секреты не добавляй в Git или ответ в публичном issue.

Сервер `server.conf`:

```ini
[Interface]
PrivateKey = <server-private-key-base64>
Address = 10.99.0.1/24
ListenPort = 51820
MTU = 1280
# Вставь сюда блок awg-tool gen, соответствующий версии образа.

[Peer]
PublicKey = <client-public-key-base64>
PresharedKey = <shared-psk-base64>
AllowedIPs = 10.99.0.2/32
```

Клиент `client.conf`:

```ini
[Interface]
PrivateKey = <client-private-key-base64>
Address = 10.99.0.2/32
DNS = 172.29.172.254
MTU = 1280
# Вставь тот же совместимый блок обфускации.

[Peer]
PublicKey = <server-public-key-base64>
PresharedKey = <shared-psk-base64>
AllowedIPs = 10.99.0.0/24, 172.29.172.254/32, 172.29.172.253/32
Endpoint = vpn.example.com:51820
PersistentKeepalive = 25
```

Для демонстрационной пары внутри Compose `Endpoint` клиента может быть `172.31.99.10:51820`. Для внешнего устройства нужен доступный публичный IP/домен сервера и опубликованный UDP-порт; контейнерное имя или bridge-IP извне недоступны. При NAT отдельно настрой проброс UDP на пограничном устройстве.

Приватные ключи сторон различаются. На сервере у `[Peer]` — публичный ключ клиента, на клиенте — публичный ключ сервера. `PresharedKey` одной пары совпадает. Серверный `AllowedIPs` ограничивает адрес **этого** клиента, обычно `/32`; не вставляй туда клиентский `0.0.0.0/0` ради выхода в интернет.

Для full-tunnel на клиенте используй `AllowedIPs = 0.0.0.0/0`. Для split-tunnel перечисли только нужные сети, включая DNS `/32` и адрес статус-страницы, если она нужна. Текущая сеть контейнера, NAT и SSH-install ориентированы на IPv4: добавление `::/0` само по себе не создаёт рабочий IPv6 или IPv6 kill switch. Не обещай отсутствие IPv6-утечек без отдельной проверки устройства.

`MTU = 1280` — консервативное значение для 3.x с дополнительным padding на пути MTU 1500. Entrypoint без `MTU` ставит 1420, а `awg-peer` без него выдаёт клиенту 1280: указывай MTU явно, чтобы не получить разные значения. Не увеличивай его до 1420 только по общему совету для обычного WireGuard.

Entrypoint читает известные ключи и сам настраивает адреса/маршруты/NAT через UAPI. Не рассчитывай на выполнение `PreUp`, `PostUp`, `PreDown`, `PostDown`, `SaveConfig`, `Table` как в `wg-quick`. Поле `DNS` в `.conf` контейнерного клиента **не переписывает** `/etc/resolv.conf`; DNS контейнера настраивается отдельно средствами Docker. Домен в `Endpoint` резолвится при старте; автоматического постоянного отслеживания смены A-записи здесь нет.

## Переменные контейнера

Значения относятся к текущим `entrypoint.sh`, `awg-peer` и Compose; флаги `awg-tool install` — другой интерфейс.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `AWG_IFACE` | `awg0` | Имя интерфейса |
| `AWG_CONF` | `/etc/amnezia/awg/${AWG_IFACE}.conf` | Смонтированный `.conf` |
| `AWG_SOCK_DIR` | `/var/run/amneziawg` | Каталог UAPI-сокета |
| `AWG_NAT` | `auto` | `on`/`off`; `auto` включает NAT при наличии `ListenPort` |
| `AWG_FWMARK`, `AWG_TABLE` | `ListenPort`, иначе `51820` | Mark/table для default route клиента |
| `AWG_STATE_DIR` | `/var/lib/awg` | Счётчик запусков и восстановление peers |
| `AWG_PEERS_DIR` | См. ниже | Каталог записей динамических peers |
| `AWG_EVENT_LOG` | `/var/log/awg/events.log` | Локальный журнал событий |
| `AWG_EVENT_LOG_MAX_BYTES` | `262144` | Размер ротации; сохраняется одна старая копия |
| `AWG_ENDPOINT` | `SERVER_PUBLIC_IP:<ListenPort>` | Внешний endpoint для новых конфигураций |
| `AWG_PUBLIC_HOST` | Не задан | Резервный host для `awg-peer`, если нет `AWG_ENDPOINT` |
| `AWG_CLIENT_DNS` | `172.29.172.254` | DNS в выдаваемом клиентском `.conf` |
| `AWG_CLIENT_ALLOWED` | `<сеть-туннеля>/24, <DNS>/32` | Маршруты в выдаваемом клиентском `.conf` |
| `AWG_DUMP_REQUEST` | `0` | `1` сохраняет секретный UAPI-запрос в `/tmp/uapi-set.req` |
| `LOG_LEVEL` | Не задан | `verbose` включает подробный лог демона |

У `awg-peer` default `AWG_PEERS_DIR=/var/lib/awg/peers.d` фиксирован, а у entrypoint он вычисляется из `AWG_STATE_DIR`. При переносе state-каталога явно задай **оба** пути одинаково, иначе новые peers и восстановление после старта смотрят в разные каталоги.

## DNS, статус-страница и маршрутизация

В штатном Compose сервер соединяет транспортную сеть `172.31.99.0/24` и отдельный DNS bridge `172.29.172.0/24`. Unbound имеет `172.29.172.254`, статус-страница — `172.29.172.253`. Ни порт 53, ни HTTP этой страницы наружу не публикуются.

- Не добавляй `ports: 53:53` ради внешних клиентов: они должны обращаться к DNS **через туннель**, а сервер — достигать bridge.
- Для split-tunnel `DNS = 172.29.172.254` требует `AllowedIPs` с `172.29.172.254/32`.
- Имя `amiunder.vpn` разрешается внутренним DNS в `172.29.172.253`. Только DNS `/32` недостаточно для открытия страницы: добавь также `172.29.172.253/32` или всю DNS-подсеть. Full-tunnel уже покрывает оба адреса.
- Fail-closed свойство относится к попытке запроса на этот приватный DNS при сохранённой изоляции сетей. Оно не блокирует системный fallback, браузерный DoH или иной VPN на устройстве; проверяй фактический клиент.
- Не подменяй tunnel-only DNS публичным `1.1.1.1`/`8.8.8.8` и не заявляй после этого прежние гарантии.
- Рекурсивному Unbound нужен исходящий DNS-доступ; отсутствие ответа может быть ограничением egress сервера, а не отсутствием handshake.

Для блокировки доменов уже есть механизм резолвера: примонтируй файл в `/etc/unbound/blacklist.d/list.txt:ro` по примеру `containers/README.md`. Допустимы домены, комментарии и hosts-строки; ответы блокировки — NXDOMAIN. Не добавляй новый обработчик списков.

## Изменение настроек

1. Зафиксируй текущие пути `.conf`, volumes, образ/digest, порт и список peers без публикации секретов.
2. Перед перезапуском предупреди об обрыве туннеля. Сохрани резервную копию конфигурации и state с правами только оператора.
3. При изменении обфускации синхронно обнови все соответствующие клиенты; при изменении endpoint/DNS/маршрутов перевыпусти или отредактируй уже выданные файлы. Изменение переменных контейнера меняет будущую выдачу, а не файлы на телефонах.
4. Изменение `environment`, образа или mount в Compose требует пересоздания сервиса через `docker compose up -d server`; простой `restart` не применяет изменённое описание контейнера. Сам `.conf` перечитывается при запуске entrypoint.
5. Не удаляй named volumes для «сброса»: там PSK и динамические peers. Утраченный state нельзя восстановить из одного только списка публичных ключей.
6. Проверь handshake и реальный DNS/трафик после изменения, а не только `healthy`. Порядок диагностики — в [operations.md](operations.md).
